# 🎮 BrightlyPK

> 一个支持在线自定义题库、实时匹配、积分制对战的答题 PK 平台。  
> 首期题库聚焦高中数学。它最初来自我和一位好友对高考体系下学习方式的一点“幻想”：
>
> **练习不一定非得像服刑，反馈也不该只能等到下一次月考。**

---

## 这个项目是什么

BrightlyPK 是一个基于 **Node.js + WebSocket** 的实时答题对战平台。

用户可以选择题目难度，进入匹配队列，与另一名玩家进行实时答题 PK。系统会根据答题正确率与速度计算得分，并在对战结束后记录战绩、错题和积分变化。

目前项目已经具备：

- 实时匹配与实时对战
- 简单 / 中等 / 困难三档题目
- 积分制结算
- 错题本与 Markdown 导出
- 好友系统、对战邀请
- 实时聊天
- 基础个人战绩统计

它不是一个成熟商业产品，更像是一个**真的被做出来了的学生项目原型**。  
技术实现有不少朴素甚至笨重的地方，但也正因为如此，它完整记录了我从“只会写静态 HTML”到第一次真正摸到全栈项目骨架的过程。

## 项目来路

这个项目做于**大一上学期**，最初是为了参加一次小挑战杯相关的校内项目。

那时候我刚从静态网页起步，对后端、实时通信、接口设计、状态管理这些东西基本都没有完整概念。

这也是我**正式入坑 Node.js** 的项目。

整个过程中，我基本负责了全部代码实现，项目文档也大多由我完成。  
小组里还有七位几乎不懂编程的队友。坦白说，他们所有人的投入时间加起来，未必有我一个人多；但项目推进中的一些杂事、材料准备、配合工作，确实也离不开他们，仍然值得感谢。

后期数学题录入，我还外包给了几位后来加入、一起蹭创新创业学分和奖项的队友。  
整体看下来，居然还真做出了点“像那么回事”的味道。

## 最初的产品设想

这个项目最开始想做的，并不只是“在线刷题”。

它想解决的是一种很常见但不太被认真对待的问题：

> 学生在学习中获得反馈的周期太长了。  
> 一次努力往往要等到周测、月考甚至期末，才知道有没有用。

所以 BrightlyPK 的核心设想是：

- 把部分练习变成轻量级竞技
- 把正确反馈缩短到分钟级
- 让进步不是抽象口号，而是能直接看到的积分、胜负、错题轨迹

在最理想的版本里，它希望服务不同层级的学生：

- **学困生**：用更短、更轻的挑战降低启动成本，重新积累“我也能做对”的体验
- **中等生**：把不明显的小进步转成可见反馈，减少长期平台期带来的倦怠
- **优等生**：通过更高质量的同层切磋，把竞争从纯排名拉回能力本身

这些想法放在今天看，当然有学生项目常见的“理想偏多、工程偏少”。  
但它们确实构成了这个项目最初的精神内核。

## 🎮 基本玩法

### 注册登录

* 首次使用需要注册账号
* 用户名长度：3–16 位
* 密码长度：6–20 位
* 注册后自动分配用户 ID

### 开始对战

1. 选择难度
2. 点击发起匹配
3. 等待系统匹配对手
4. 匹配成功后进入答题界面
5. 对战结束后进行积分结算

### 对战规则

* 每场固定题量
* 每题有限时
* 正确率与速度共同影响得分
* 超时视为未作答

这个项目的实现方式非常“入门项目”：

* 数据直接落在 JSON 文件里
* 服务端逻辑集中在单文件

> 从零开始，哪怕一开始什么都不懂，也确实能把一个相对完整的实时 Web 项目一点点搭出来。

## 题目管理说明

现阶段题目主要通过直接编辑 JSON 文件维护，因此格式需要格外小心。

### 基本规范

* JSON 中的公式斜线需要双重转义
* 大于号、小于号建议使用 LaTeX：

  * `\\lt`
  * `\\gt`
* 填空题：

  * `options` 为空数组
  * `type` 为 `"fill"`

### 当前难度映射

```text
easy   : 1-3, 12
medium : 4-6, 13
hard   : 7-8, 14
```
